# QA Documentation – DentalBookingApp

## 1. Project Overview
**DentalBookingApp** is a mobile application designed to digitize and optimize dental clinic management processes.  
The application supports appointment booking, medical record management, online shopping, and system administration.

This repository contains **Quality Assurance (QA) documentation** created for an academic project, focusing on **manual testing** and test reporting.

---

## 2. QA Scope
The QA activities cover the following testing types:

- Manual Functional Testing  
- GUI / UI Testing  
- Validation Testing  
- Regression Testing  
- Exploratory Testing  

### In-scope features:
- User Authentication (Register / Login / Logout / Forgot Password)  
- Appointment Booking & Management  
- Medical Records & Treatment History  
- Online Shopping & Order Management  
- Admin & Staff Web Management  

### Out-of-scope:
- Advanced Security Testing (Penetration Testing)  
- Load / Stress Testing  
- External Payment Gateway Integration  

---

## 3. Test Environment
- **Platform:** Android Emulator (Pixel 6 – API 34)  
- **Backend:** Firebase (Authentication & Firestore – Test Mode)  
- **Tools:**  
  - Excel (Test Case management)  
  - Google Docs / Word (Test Plan & Test Summary)  
  - GitHub (Version control)  

---

## 4. QA Artifacts
The following QA documents are included in this repository:

| Document | Description |
|--------|------------|
| `Test_Plan.docx` | Defines test scope, strategy, environment, entry/exit criteria |
| `Test_Case.xlsx` | Detailed manual test cases with expected & actual results |
| `Test_Summary.docx` | Final test report with execution results and recommendations |

---

## 5. Testing Approach
- Requirements-based testing using Use Case and Activity Diagrams  
- Combination of:
  - Test case–based testing  
  - Exploratory testing  
- Positive & negative test scenarios applied to all core features  
- Regression testing performed after bug fixes  

---

## 6. Test Results Summary
- **Total test cases executed:** 71  
- **Pass rate:** 100%  
- **Critical / High defects:** 0  
- **Requirement coverage:** 100%  

The application meets all defined exit criteria and is considered **ready for release** in the testing environment.
